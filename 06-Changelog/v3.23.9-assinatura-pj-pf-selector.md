# v3.23.9 — Seletor PJ/PF na assinatura digital de propostas

**Data:** 2026-05-21
**Origem:** CEO testou PROP-2026-0015 em produção (v3.23.8 com 3 fixes). PDF e parcelas OK, mas ao clicar "Assinar" não tinha opção de escolher PF — o `confirm()` antigo era hardcoded "e-CNPJ Romatec" e o código backend chamava `getCertForSigning('pj')` fixo. Como o CEO tem só o cert PF cadastrado, a assinatura travava.

## Decisão

Opção **B** do diagnóstico anterior: implementar modal seletor PJ/PF (não só o quick fix de trocar 'pj' por 'pf'). O CEO em algum momento vai cadastrar PJ também, e aí precisa escolher.

## Backend (`propostasConsultoria.ts`)

`assinarProposta` agora aceita parâmetro `perfil`:

```typescript
export async function assinarProposta(
  propostaId: number | string,
  perfil: 'pj' | 'pf' = 'pj',          // default 'pj' por retrocompat
): Promise<AssinarPropostaResult> {
  if (perfil !== 'pj' && perfil !== 'pf') {
    throw new Error(`perfil invalido: ${perfil}`);
  }
  const certData = await getCertForSigning(perfil);
  if (!certData) {
    const tipo = perfil === 'pj' ? 'e-CNPJ' : 'e-CPF';
    throw new Error(`Nenhum certificado digital ${perfil.toUpperCase()} cadastrado. Cadastre o ${tipo} ICP-Brasil A1...`);
  }
  // ...
  const meta = { perfil, /* resto */ };  // perfil agora vai no JSON do banco
}
```

`meta.perfil` (gravado em `propostas.assinatura_meta` JSON) reflete o perfil real usado, não mais hardcoded `'pj'`.

## Endpoint (`server.ts`)

`POST /api/propostas-consultoria/:id/assinar` parseia body:

```typescript
const body = req.body || {};
const rawPerfil = body.perfil ?? body.tipo_certificado ?? 'pj';
const perfil = (rawPerfil === 'pf' || rawPerfil === 'e_cpf') ? 'pf' : 'pj';
await assinarProposta(req.params.id, perfil);
```

Aceita `perfil` e o alias `tipo_certificado` (suporta `e_cnpj`/`e_cpf` também — brief original usava esses nomes).

## Frontend (`obras.html`)

Substituído o `confirm()` antigo por modal customizado `abrirModalAssinatura(propostaId, btnTrigger)`:

- Busca `/api/signing-cert` → lista todos os certs cadastrados
- Filtra `ativo === true && expirado === false`
- Renderiza 1 card por cert disponível (PJ e/ou PF):
  - **PJ:** ícone 🏢 cor azul `#3b82f6`, descrição "PJ — Propostas comerciais, contratos, NFS-e"
  - **PF:** ícone 👤 cor roxa `#a855f7`, descrição "PF — Laudos, ART/TRT, peças com responsabilidade técnica pessoal"
  - Cada card mostra: tipo + label da Romatec, titular (subject_cn), documento formatado (CPF/CNPJ), dias para vencer (verde se >60d, warning se <60d)
- Radio com default PJ se ambos existirem (PF se só PF). Card selecionado ganha borda colorida + fundo destacado.
- Botão "🔐 Assinar com certificado selecionado" envia POST com body `{ perfil: 'pj' | 'pf' }`
- Aviso azul: "🔐 Assinatura ICP-Brasil A1 (PAdES). Validável no Adobe Reader e em validar.iti.gov.br."

Se nenhum cert ativo: alert "Cadastre um e-CPF ou e-CNPJ ICP-Brasil A1 em /obras admin (botão 🔏 Certs no header) antes de assinar."
