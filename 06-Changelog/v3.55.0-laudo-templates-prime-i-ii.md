# v3.55.0 — Templates Prime I e II para Laudos de Demarcação

## Resumo
Adiciona os templates **Prime I** (premium verde/dourado) e **Prime II** (executivo
azul-escuro/verde-zayra) à exportação de PDF dos Laudos de Demarcação, replicando o
módulo paralelo Puppeteer já usado em Propostas e Recibos. O template **padrão**
(PDFKit) permanece **intocado** — apenas novas opções de exportação foram adicionadas.

| Template | Estilo | Pipeline |
|---|---|---|
| Padrão | tradicional Romatec | PDFKit (`laudoPdf.ts`) — inalterado |
| Prime I | dark premium verde `#0B6E4F` / dourado | Puppeteer (HTML→PDF) |
| Prime II | executivo `#1A1A2E` / verde-zayra `#00ff88` | Puppeteer (HTML→PDF) |

## Arquitetura (módulo paralelo `src/pdf/`)
- **`types/templateTypes.ts`**: + interface `LaudoDados` (+ `LaudoVertice`, `LaudoLado`,
  `LaudoTecnico`). Reusa o enum `TemplateId` existente (`padrao`/`prime1`/`prime2`).
- **`pdf/mappers.ts`**: + `laudoToLaudoDados(laudo, contratante, executante, pontos, lados, baseUrl, croquiSvg?)`
  e `TECNICO_ROMATEC_LAUDO` (CFT/CNAI/CRECI/INCRA). Área em m²/ha/alqueires
  (alqueire do norte = 4,84 ha) só para imóvel RURAL.
- **`pdf/templates/laudoTemplatePrime1.ts` + `laudoTemplatePrime2.ts`**: `buildLaudoPrimeNHtml`
  (puro/testável) + `gerarLaudoPdfPrimeN` (async, QR + `htmlToPdf`). Todas as 12 seções:
  cabeçalho, identificação, contratante, imóvel, finalidade, tabela de vértices, tabela
  de lados, box de área, croqui (SVG inline), ART/TRT, assinatura, validação (hash+QR).
- **`pdf/laudoPdfRouter.ts`**: `gerarLaudoPdf(dados, templateId)` despacha Prime1/Prime2.
- **`routes/pdfPrime.ts`**: + rota `GET /api/pdf-prime/laudo/:id?template=prime1|prime2`
  (busca laudo+contratante+executante+pontos+lados, gera croqui best-effort, mapeia, gera).

## Fix do rodapé (sobreposição da paginação)
Ambos os templates usam `displayHeaderFooter:true` + `footerTemplate` do Puppeteer
(paginação "Pág. X de Y" / "X / Y") com `margin.bottom = 18mm`, eliminando a
sobreposição com o conteúdo. `@page { margin:0 }` + padding lateral próprio do body.

## Frontend (`obras.html`)
O botão "📄 PDF" do card do laudo virou um **dropdown** nativo (`<details>`, sem
Bootstrap): Padrão / ✨ Prime I / 💎 Prime II. `exportarLaudoPdf(id, template)` —
padrão usa a rota PDFKit atual (retrocompatível), Prime usa `/api/pdf-prime/laudo`.

## Verificação
- Testes Vitest dos `buildLaudoPrimeNHtml` (puros) + do mapper (`mappers.laudo.test.ts`).
- `tsc --noEmit`: 0 erros.

## Desvios do spec original (impostos pela arquitetura real, conforme "reutilizar, não recriar")
- Rota Prime é o módulo paralelo `/api/pdf-prime/laudo/:id` (como proposta/recibo),
  não uma extensão de `/api/laudos-demarcacao/:id/pdf`. O padrão fica na rota atual.
- Frontend é `obras.html` com JS inline (não EJS/Bootstrap) — dropdown via `<details>`.
- Versão só no `package.json` (fonte única; `identity.ts` lê em runtime, `sw.js` usa
  placeholder — editar os três quebraria o teste `versao-fonte-unica`).
