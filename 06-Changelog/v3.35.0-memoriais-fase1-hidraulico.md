## Mudanças por arquivo

### Backend

- `src/database/migrations-memoriais.ts` (NOVO) — 2 tabelas idempotentes:
  - `memoriais_calculo` (core: código `MEM-AAAA-NNNN-XXX-R1`, disciplina enum, obra/cliente/user, snapshot do PDF, wizard_responses JSON, status enum, TRT/ART, assinatura, envios)
  - `sinapi_indices` + seed de 15 índices (NBR 5626 / NBR 8160 / NBR 5410 / TIGRE / SINAPI)
- `src/services/memoriais/types.ts` (NOVO) — `DisciplinaMemorial`, `StatusMemorial`, `WizardComum`, `WizardHidraulico`, `AparelhoHidraulico`, `MemorialHidraulicoOutput`, `PdfExtractionResult`.
- `src/services/memoriais/hidraulicoCalc.ts` (NOVO) — engine NBR 5626 standalone:
  - `calcularConsumoDiario()` — pessoas × 150 + extras + 10% reserva
  - `calcularReservatorio()` — V_mínimo = 2 × consumo; arredonda em múltiplos de 250 L
  - `calcularVazaoProjeto()` — Q = 0.3 × √(ΣP)
  - `somarPesos()` — pesos NBR 5626 Tabela 1 (8 aparelhos)
  - `dimensionarBarrilete()` — escolhe menor DN onde v ≤ 3.0 m/s (Tabela TIGRE)
  - `calcularMemorialHidraulico()` — orquestrador
- `src/services/memoriais/memorialPdfParser.ts` (NOVO) — heurística Revit:
  - `extrairMetadados()` — proprietário, CPF/CNPJ, área, quadra/lote, prancha (PH-03 etc), município/UF
  - `extrairTabelas()` — `Tabela X.X - Título` + cabeçalho + linhas
  - `detectarProdutoInexistente()` — comum em Revit (família custom sem schedule)
  - `calcularConfianca()` — score 0-1
  - `parsePlantaPdf()` — orquestrador (lazy `pdf-parse`)
- `src/services/memoriais/wizardEngine.ts` (NOVO) — catálogo tipado de perguntas:
  - Perguntas comuns (uso, pessoas, área, pavimentos, TRT)
  - Perguntas Hidráulico (fonte, reservatório, aquecimento, máquina lavar, limpeza)
  - Placeholder "em breve" para outras disciplinas
  - `listarDisciplinasDisponiveis()` para o catálogo da UI
- `src/repositories/memoriaisRepo.ts` (NOVO) — `criar`, `buscarPorId`, `listar`, `atualizarStatus`, `softDelete` + geração de código sequencial por ano e disciplina.
- `src/server.ts` — 6 endpoints novos:
  - `GET /api/memoriais/disciplinas` (pública — catálogo)
  - `GET /api/memoriais/:disciplina/wizard` (pública — campos do wizard)
  - `POST /api/memoriais/upload-pdf` (auth — extrai metadados do PDF)
  - `POST /api/memoriais/hidraulico/calcular` (auth — preview sem persistir)
  - `POST /api/memoriais/:disciplina/criar` (auth — só `hidraulico` em Fase 1)
  - `GET /api/memoriais/:id` (auth) + `GET /api/memoriais` (auth, listar/filtrar)
  - Migration registrada no boot

### Frontend

- `src/public/obras.html`:
  - Nova aba `📐 Memoriais & Quantitativos` (entre Cálculos e Configurações)
  - `renderMemoriaisQuantitativos()` — grid de 5 cards de disciplina (Hidráulico ativo, 4 "Em breve") + histórico de memoriais gerados
  - `abrirWizardHidraulico()` — wizard completo em 4 passos:
    1. Upload PDF (opcional — auto-preenche metadados)
    2. Dados da obra (título, endereço, proprietário, área, prancha)
    3. Dados hidráulicos (pessoas, fonte, máq lavar, limpeza)

  - Botão "💾 Salvar memorial" → POST `/api/memoriais/hidraulico/criar`

## Endpoints

```
GET    /api/memoriais/disciplinas                            (público)
       → { disciplinas: [{ slug, rotulo, icone, norma, disponivel }] }

GET    /api/memoriais/:disciplina/wizard                     (público)
       → { disciplina, campos: WizardCampo[], disponivel }

POST   /api/memoriais/upload-pdf                             (requireAuth)
       Body: { pdf_b64 } (max 30 MB)
       → { metadados, tabelas, produtos_inexistentes, confianca }

POST   /api/memoriais/hidraulico/calcular                    (requireAuth)
       Body: WizardHidraulico
       → MemorialHidraulicoOutput

POST   /api/memoriais/:disciplina/criar                      (requireAuth, só 'hidraulico')
       Body: { obra_titulo, obra_endereco, proprietario_nome, area_construida_m2, ... }
       → { id, codigo }

GET    /api/memoriais/:id                                    (requireAuth)
GET    /api/memoriais?disciplina=&status=&obra_id=&limite=   (requireAuth)
```
