# v3.24.1 — PR B: Colaborador self-service (/minha-quinzena + seed Leonardo)

**Data:** 2026-05-21
**Origem:** Continuação da PR A (v3.24.0 Auth Foundation). Agora que colaboradores conseguem logar, esta PR cria a **view exclusiva deles** (`/minha-quinzena`) com 3 cards (saldo a receber, dias da quinzena, vales) + histórico de pagamentos, mais o **middleware de ownership** (`requireColaboradorOwnership`) que garante que cada colaborador só vê os próprios dados. ## Arquivos alterados

- `src/middleware/auth.ts` — adicionado `requireColaboradorOwnership(req, res, next)`:
  - Se role != colaborador: passa (admin/gestor podem ver tudo)

  - Se :colaboradorId/:funcionarioId/:equipeId no path ou ?colaborador_id/?funcionario_id/?equipe_id no query, compara com user.equipe_id e bloqueia 403 se diferente
  - Suporta variações de nome do param: colaboradorId, funcionarioId, equipeId, colaborador_id
- `src/server.ts`:

## Endpoints expostos

| Endpoint | Auth | Descrição |
|---|---|---|
| `GET /api/minha-quinzena` | `requireAuth` + `requireColaboradorOwnership` | Resumo do mês: dias, vales, saldo. Aceita `?ano=2026&mes=5` (default = mês corrente). Admin/gestor pode passar `?funcionario_id=X` |

## Seed script `scripts/seed-colaborador-leonardo.ts`

Uso (local, apontando pro Railway DB via `.env`):
```bash
npx tsx scripts/seed-colaborador-leonardo.ts
```

O que faz:
1. Procura `"Leonardo da Silva Oliveira"` em `romatec_obra_equipe` via `LIKE`. Se não achar, lista 10 ativos pra confirmar nome
2. Cria registro em `users` (email `leonardo.silva@romatec.local`, hash bcrypt cost 12, senha temporária de 8 chars sem ambiguidade — sem `0/O/1/l/I`)
3. Cria registro em `tenant_users` com `role='colaborador'` + `equipe_id=<leonardo.id>` + `tenant_id=1`
4. Imprime credenciais **uma única vez** (login + senha) no console
5. **Não envia WhatsApp** — CEO dispara manualmente (PR C automatiza)

Idempotente — se já existir user com o mesmo email, atualiza apenas o vínculo `tenant_users.equipe_id` (sem regenerar senha). Pra resetar, apaga manual antes:
```sql
DELETE FROM tenant_users WHERE user_id = <X>;
DELETE FROM users WHERE id = <X>;
```
